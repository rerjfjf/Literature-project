# Электронный учебник

Сайт-читалка для электронного учебника: авторы, темы, оглавление, поиск, титульный лист, фото/QR-зоны, тренажёры, ИИ-диалог, поля ответов к заданиям, кабинеты ученика/преподавателя/администратора и адаптация под мобильный экран.

## Как запустить

Теперь проект запускается через сервер, чтобы работали кабинеты, группы и сохранение оценок.

```bash
cd /Users/nikitasokovyh/Book
npm start
```

После запуска откройте:

`http://localhost:4173`

Быстрый запуск через скрипт:

```bash
bash /Users/nikitasokovyh/Book/start-book.sh
```

Все пользователи регистрируются как ученики. Администратор может назначить роль преподавателя или администратора из кабинета администратора.

## Как заменить демонстрационный текст

Контент находится в `content.js`. Структура:

- `title` - название учебника;
- `authorId` - технический id автора для QR-кода и сохранения ответов;
- `authors` - список авторов для левого меню;
- `subtitle` - подпись в оглавлении;
- `chapters` - главы;
- `sections` - разделы внутри главы;
- `blocks` - абзацы, подзаголовки, списки, таблицы, заметки и цитаты.

У каждого раздела есть `id`. Его лучше не менять после публикации: по нему работают ссылки, оглавление и будущая привязка заданий.

## QR-коды

Положите PNG-файл в папку `qrcodes` и назовите его по `authorId`.

Для текущих авторов:

`qrcodes/tvardovsky.png`

`qrcodes/okudzhava.png`

`qrcodes/zabolotsky.png`

`qrcodes/vysotsky.png`

QR для титульного листа нейросети:

`qrcodes/neural-network.png`

## Фото

Положите изображения авторов в папку `images`:

`images/tvardovsky.jpg`

`images/okudzhava.jpg`

`images/zabolotsky.jpg`

`images/vysotsky.jpg`

Титульная иллюстрация:

`images/title.jpg`

Если файла пока нет, сайт покажет аккуратную заглушку.

## Тренажёры

Тренажёры работают без ИИ и сразу считают результат в браузере. Для каждого произведения добавлены три уровня: понимание текста, анализ, позиция и творческое применение.

## ИИ-диалог

Кнопка `ИИ-диалог` открывает отдельное окно общения по текущему автору и разделу. Для работы нужен API-ключ в `.env` и вход в аккаунт.

> ⚠️ ИИ работает через GROQ. В начале 2026 года модели `llama-3.3-70b-versatile` больше не существует на ключах GROQ, поэтому по умолчанию сервер использует `qwen/qwen3.8-27b`. Если хотите другую модель — задайте переменную окружения `SCORING_MODEL`. Список доступных моделей вашего ключа:
> `curl https://api.groq.com/openai/v1/models -H "Authorization: Bearer $GROQ_API_KEY"`

## Поля ответов и оценка

Ответы учеников отправляются на сервер, проверяются ИИ и сохраняются в `data/db.json`. После выставления оценки работа блокируется для ученика.

Сервер читает API-ключ из `.env`. Поддерживается формат:

```env
GROQ_API_KEY=...
```

Если в `.env` лежит только сам ключ одной строкой, сервер тоже его прочитает.

Полная защита от сброса теперь сделана через серверное хранение: перезагрузка страницы или очистка браузера не удаляет оценку из `data/db.json`.

### Хранение данных: файлы или PostgreSQL

По умолчанию все данные (пользователи, группы, оценки, видеотека) лежат в
`data/db.json` и `data/videos.json`. Если задать переменную окружения
`DATABASE_URL`, сервер автоматически **дублирует** всё в PostgreSQL (таблица
`book_state`): на старте данные загружаются из Postgres, каждая запись сразу же
сохраняется в файл и в базу. Строка подключения:

```env
DATABASE_URL=postgresql://user:password@host:5432/dbname
```

Без `DATABASE_URL` поведение полностью прежнее — только файлы.

## Деплой на Render (бесплатный тариф)

Проект готов к хостингу: в корне лежит `render.yaml` (Blueprint). Шаги:

### 1. Подготовка репозитория на GitHub

Render разворачивает проект из GitHub-репозитория. Сейчас в папке нет `.git`, поэтому:

```bash
cd /Users/nikitasokovyh/Book
git init
git add -A
git commit -m "Initial commit"
# создайте пустой репозиторий на github.com → скопируйте его адрес
git remote add origin https://github.com/ВАШ_ЛОГИН/book.git
git push -u origin main
```

`.env`, `data/`, `node_modules/` уже в `.gitignore` — секрет GROQ не попадёт в GitHub.
⚠️ **Перед пушем замените ключ GROQ**: старый ключ был виден в `.env.example` (сейчас там заглушки). Создайте новый ключ на https://console.groq.com/keys и обновите `.env` локально, а на Render впишите новый.

### 2. Создание сервиса на Render

1. Зарегистрируйтесь на https://render.com (можно через GitHub).
2. **Dashboard → New → Blueprint** и выберите ваш репозиторий.
3. Render прочитает `render.yaml` и сам создаст Web Service `book`.
4. Откройте сервис → **Environment** и задайте значения для секретов
   (те, что с `sync: false`, Render их сгенерирует, но лучше вписать свои):
   - `GROQ_API_KEY` — ваш новый ключ `gsk_...`;
   - `JWT_SECRET` — любая длинная случайная строка (например, `openssl rand -hex 32`);
   - `PORTAL_SECRET` — общий секрет SSO (должен совпадать с другими сервисами);
   - `VIDEO_ADMIN_PASSWORD` — пароль админки видеотеки;
   - `DATABASE_URL` — строка подключения к PostgreSQL (см. ниже);
   - `BOOK_URL` — адрес вашего сервиса вида `https://book-xxxx.onrender.com`
     (появится после первого деплоя; можно дописать потом);
   - `DIALOG_URL`, `LITFAIR_URL` — если будете деплоить соседние сервисы;
   - `SCORING_MODEL` — необязательно, по умолчанию `qwen/qwen3.8-27b`.
5. Нажмите **Manual Deploy → Deploy latest commit**.

Адрес вида `https://book-xxxx.onrender.com` — готовый HTTPS-сайт.

### 2а. Где взять бесплатный PostgreSQL (чтобы данные не стирались)

На бесплатном тарифе Render у сервиса эфемерный диск — файлы `data/*.json`
стираются при каждом ре-деплое. Поэтому задайте `DATABASE_URL`, и сервер будет
хранить всё в внешней базе:

- **Neon** (проще всего): https://neon.tech → создать аккаунт (можно через GitHub)
  → **Create project** → скопировать строку подключения вида
  `postgresql://...` → вставить в `DATABASE_URL` на Render. У Neon бесплатный
  тариф не имеет срока годности.
- **Render PostgreSQL**: Dashboard → **New → PostgreSQL** (если доступен в вашем
  аккаунте), скопируйте `Internal Database URL`. Обратите внимание: бесплатные
  базы на Render могут иметь срок жизни ~30 дней.
- Платный тариф Render (от ~$7/мес.) даёт постоянный диск — тогда Postgres
  не обязателен.

### 3. Ограничения бесплатного тарифа (важно!)

- **Холодный старт.** Сервер засыпает после ~15 минут без запросов. Первый
  запрос после простоя занимает 15–60 секунд (пока контейнер проснётся).
  Пинговайте его раз в 10 минут (напр. cron) — тогда сайт открывается быстро.
- **Лимит 750 часов в месяц.** При постоянной работе (24/7) этого не хватит —
  Render попросит перейти на платный тариф. Для школьного проекта (учёба днём)
  обычно хватает.
- **Эфемерный диск.** Файлы `data/*.json` стираются при ре-деплое/перезапуске.
  Это решается через `DATABASE_URL` (раздел 2а). После первого запуска с базой
  данные загружаются из Postgres, а локальные файлы остаются лишь резервной
  копией.

### 4. Проверка после деплоя

- Откройте `/api/health` — должно вернуть `{"ok":true}`.
- Откройте `/api/ai/health` будучи залогиненным — должно вернуть
  `{"ok":true,"provider":"groq","model":"qwen/qwen3.8-27b"}`.
- Откройте главную страницу, войдите, попробуйте «ИИ-диалог» у любого раздела.
